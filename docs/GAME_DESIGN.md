# GAME DESIGN

## 1. コンセプト

`NULL CASE` は、複数のデータベースに残された「個別には正しいが、組み合わせると矛盾する記録」から事件を再構築する捜査ミステリーです。主人公をフィールド上で移動させず、統合捜査端末そのものをゲーム世界として扱います。

## 2. プレイヤー体験

1. 事件概要から最初の違和感を得る
2. 調べるべきデータソースを選ぶ
3. SQL、ログ検索、グラフ探索などで記録を絞り込む
4. 異常な行を証拠として保存する
5. ケースボードで人物・場所・記録を接続する
6. 犯人、動機、方法、時刻、根拠を事件モデルとして提出する
7. 提出内容に応じて真相とエンディングが変化する

## 3. 中核原則

- **矛盾がゲームプレイ**：検索件数やSQL知識ではなく、データ間の不一致を発見することが中心。
- **不在も証拠**：0件、欠損値、連番の欠落、更新時刻のズレにも意味を持たせる。
- **ツールごとに視点が違う**：同じ検索UIの着せ替えにせず、DBの特性が推理を変える。
- **プレイヤーが結論を作る**：最終解答は単一選択ではなく、証拠付きの事件モデルにする。
- **専門知識を壁にしない**：プリセット、スキーマ、段階ヒントを用意し、初心者も完走できる。

## 4. CASE 001 の縦切り範囲

### 導入

HOTEL ARGOSの404号室で身元不明男性の遺体が発見される。しかしHOTEL DBの部屋マスタでは、4階は403号室の次が405号室になっている。

### データソース

| データソース | 操作 | 得られる視点 |
| --- | --- | --- |
| HOTEL DB | SQL風検索 | 部屋、宿泊客、予約 |
| ACCESS DB | 条件フィルター | カードキーと入退室 |
| CAMERA DB | 時刻・人物タグ検索 | 映像メタデータ |
| PAYMENT DB | 取引検索 | 注文と支払者 |
| FACILITY DB | 時系列グラフ | 電力・空調・エレベーター |
| STAFF DB | 人物・組織グラフ | 従業員と権限 |

### 完成条件

- 犯人・動機・侵入方法・死亡時刻を特定できる
- 各結論に必要な証拠を関連付けられる
- 誤った推理も提出でき、内容に応じた評価が返る
- 45〜75分で完走できる

## 5. 難易度設計

| モード | 支援内容 |
| --- | --- |
| Story | 推奨クエリを表示し、重要行を弱く強調 |
| Investigator | スキーマと検索例だけ表示 |
| Analyst | 例を隠し、ヒント使用回数を記録 |

## 6. 非目標

- 任意SQLを完全再現する学習ツール
- 実在人物・企業・宿泊施設のデータ利用
- 生成AIが毎回真相を変える自動事件生成
- MMOやリアルタイム対戦
