## 自由記述と採点

M06の自由記述と根拠説明は維持する。単語を含むかどうかで自然文を採点しない。「神代ではない」と「神代だ」を同じ判定にする実装は不可。

M07では評価用に4項目の構造化した結論IDを追加した。各項目に対立仮説を用意し、選択肢に正解印や必要証拠IDを含めない。時刻は幅を持つ候補を用意する。自由記述はプレイヤーの説明として保存し、自動判定の対象は結論IDと証拠割当であることをUIに明示する。

選択肢そのものが未発見の設定を先に明かす問題を避けるため、少なくとも対応する記録を発見した後に候補を開示する。誤答候補を含む公開候補一覧は採点用正解一覧から分離する。

## 評価処理と返却範囲

`src/server/evaluation/evaluateCaseModel.ts`に汎用の純粋な採点コアを実装済み。`case001.ts`がserver-only境界内で実事件の正解表を読み込み、`POST /api/cases/case-001/evaluate`から呼び出す。合成データと実事件の証拠で次を検証する。

- 全項目が正しい主張＋必要証拠：`supported`
- 主張は正しいが割当証拠不足：`incomplete`
- 誤った主張を含む：`revise`
- 項目別：`supported` / `insufficient_evidence` / `revise_claim`
- 未登録・未知・重複の証拠ID、不正な結論ID、余計なフィールドは入力エラー

返却するのは判定状態と採点表バージョン。全項目支持の場合だけ解決文を含め、正しい結論ID・不足している証拠ID・採点表は返さない。Route HandlerはJSON、64KiB上限、入力形式とIDを検証し、no-storeで応答する。ブラウザからは15秒でタイムアウトし、再試行可能。server-only境界に加え、ビルド後の.next/staticに正解表・解決文が存在しないことを確認した。

現行保存はlocalStorageであり、サーバーが発見済み状態を証明できる仕組みはない。ブラウザ申告の登録IDをそのまま信頼して「不正防止済み」とは言わない。試遊版ではこの限界を受け入れ、競技性が必要になった時点でサーバー側の進捗管理を導入する。
