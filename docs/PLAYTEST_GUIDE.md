# CASE 001 初見試遊手順

目的は、初見プレイヤーが証拠から結論を組み立て、45〜75分で解決できるかを確認すること。自動E2Eの成功とは別に評価する。現時点で人による試遊は未実施。

## 準備

- 初見の参加者3人を対象とし、各自に新しいブラウザプロファイルを用意する。既存の捜査保存は削除しない。
- `npm run build`、`npm start`で起動。画面幅、ブラウザ、キーボード／タッチ、SQL経験を記録する。
- 参加者にはゲーム画面だけを見せる。正解表・追加設定資料・解決テストは見せない。
- 導入会話の開始時刻と、端末へ移った時刻をそれぞれ記録。詰まった場所と考えていることを任意で話してもらう。
- 導入の読み飛ばし、案内の使用／スキップ、最初の証拠までに操作説明が必要だった回数を記録する。会話と操作案内で目的・次の行動が伝わったかを終了後に尋ねる。

## 観察

操作方法への質問には答え、解答そのものは示さない。ヒントを求められた場合は、まず画面内のスキーマ・検索例・追加資料の案内へ誘導し、時刻と伝えた内容を記録する。

| 項目 | 記録 |
| --- | --- |
| 匿名参加者ID／環境／SQL経験 | |
| 開始／終了／休憩時間 | |
| 最初の0件と最初の証拠登録までの時間 | |
| 各追加資料を発見・登録した時刻 | |
| 操作で迷った場所と継続時間 | |
| ヒントの時刻・内容 | |
| 提出回数／根拠不足・誤答からの修正 | |
| 解決／中断と理由 | |
| 結論と根拠を自分の言葉で説明できたか | |

終了後に、証拠の信頼性、結論への飛躍、説明不足の操作、読みづらさを尋ねる。採点上の正解と、物語として納得できたかを分けて記録する。

## 判定と調整

運営側は終了後に評価設計と照合し、追加の必須8記録について「発見した人数÷参加人数」を記録する。重要証拠ごとの発見率80%以上、3人ともヒント込みで完走、各結論の理由を説明できることを目標とする。少人数の結果であり、全プレイヤーへの一般化はしない。

発見率が低い記録は検索導線・案内文、操作で詰まる場所はUIを先に見直す。正解・証拠文面を変更する場合は根拠を記録し、既存の事件設定との整合性を確認する。未達項目は開発計画に残し、未実施の試遊を完了扱いにしない。
